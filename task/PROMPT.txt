我需要在审批台上回答一个问题：同一个人分属两个研究队列时，为什么两个各自合规的统计报告联发却超预算？请开发一个离线隐私发布审计程序。隐私消耗按下面的合同规则计算，直接使用试验数据里的有理数成本，程序不设计修改数据或训练真实模型的机制。参与者、队列与发布项全部虚构。

每个发布绑定不可重用的发布 ID、查询批次、真实使用的队列快照与用途组。队列快照是带版本的多集，计算暴露成本时同一人在同一发布中重复出现只计一次；补报历史人口变化不能重写旧发布的暴露集合。身份对照表随有效期演进，合并后须把相应旧发布代价合并计算，但同一发布里的两个旧号也只收费一次。拆分应按不可变的来源成员记录重新归属，有含糊映射时按输入给出的候选解释审查；不同发布中指向同一来源成员的选择必须一致。被要求撤回的发布仍按已经发生的成本计入，只有未提交的草稿可撤回退款。

按用途组及时间窗对每人求精确有理数消耗。审计返回预算是否在每种可行身份解释下合规，证明超额要给参与者对应的抽象来源、发布集合、精确分数与一组完整可行身份解释；违反项按时间窗、用途、来源排序。recheck 在新对照表录入后回看任一历史审计视图，再报告哪些结论变化。choose 在待发布候选中挑一个固定子集，保留全部强制发布，在任一身份解释下都保持预算；优先最大化输入给定的研究价值，再最小化新增的最坏个人消耗，最后取最小的发布 ID 列表。价值和预算上限取自输入，窗口左闭右开。提供独立小规模穷举，覆盖合并后旧账同一次去重、拆分时需共同选择、恰在窗末、撤下已发报表不返还、以及浮点近似会将严格超预算当作合规。规模支持 20 个候选、30 个身份选择和 200 个窗口。

依靠 Windows 的原生 Python 3.12 标准库和 CPU 从零实现；交付可运行的合成研究案例。python -m release_budget <命令> CASE.json 返回确定性 UTF-8 JSON，输入报错需可追到字段和记录。把完整接口及回归命令写进 README，断言测试使用 unittest。
